# KUKI GYMRATS トレーニング管理システム（デモアプリ）

## 🎯 プロジェクトの目的
KUKI GYMRATSの選手41名が行う週1〜2回のウエイトトレーニングのデータをデジタル化・可視化し、選手の成長を最大化する。
併せてペーパーレス化によるコーチ・トレーナーの管理負担軽減、コンディション管理（痛み・補食）を通じた怪我の予防と個別最適化（リハビリ選手・希望選択型メニュー対応）を実現し、チームの「日本一」達成を支援する。

本システムは、選手がスマートフォンから日々のコンディションとトレーニング実績を入力・確認できる**選手用モバイルアプリ**と、コーチ・トレーナーがPCからメニュー配信や全選手の状態を一元管理できる**管理ダッシュボード**を一体化した静的Webアプリケーション（デモ版）です。

---

## ✅ 現在実装済みの機能

### 1. ログイン選択画面（`index.html`）
- コーチ・トレーナー・選手41名からユーザーを選択してログイン（デモ用の簡易ログイン、パスワード認証なし）
- 選手は背番号・氏名で検索可能
- リハビリ中の選手はハイライト表示

### 2. 選手用モバイルアプリ（`player.html`）
- **コンディション管理**
  - 補食実施チェック（ON/OFFトグル、即時保存）
  - 痛み・違和感トグル → ONの場合、簡易ボディマップ（人体シルエット図）から部位をタップして選択、5段階の痛みレベルを設定
  - リハビリ中の選手には専用バナー表示
- **ウエイトトレーニング記録（セット単位管理）**
  - 本日配信されたメニューを**種目カード×セット行**で表示。1種目内でもセットごとに目標重量・回数が異なる場合に対応（例：バックスクワット5セットでウォームアップ→本セットへピラミッド式に重量アップ）
  - 目標重量はセットごとの強度（%）× 直近の1RM から自動算出
  - 各セットに個別の「＋/−」ステッパー（重量2.5kg単位・回数1回単位）とチェックボタンを配置
  - セット完了後も重量・回数・完了状態はいつでも修正可能（ロックしない）
- **成長グラフ**
  - 種目別に1RM推移を折れ線グラフで表示（Chart.js）
  - 最新1RM・期間中の伸びを表示
- **振り返り（新規）**
  - 本日のトレーニングの振り返りを記入・更新（できたこと・課題・体の状態など）
  - チーム全員の振り返り投稿を時系列で確認
  - 他選手・コーチ・トレーナーの投稿にコメントを送信できる（コメントスレッド形式）
- **メニュー希望（オプトイン）**
  - ジャンプ力向上プログラムなどの希望メニューをリクエスト。選択肢に「その他（自由入力）」を追加し、任意の希望メニュー内容をテキストで入力可能
  - 申請履歴と承認状況（承認待ち／承認済み／却下）を確認

> 🔒 **選手登録は管理者（コーチ・トレーナー）のみ可能**：選手の新規登録・編集・退部操作は、コーチ・トレーナーとしてログインした場合のみ表示される「選手管理・成長」画面に限定しています。ログイン選択画面（`index.html`）・選手用アプリ（`player.html`）には登録・編集の入口を一切設けておらず、選手自身による自己登録はできません。（`dashboard.html`側の`init()`は`role`がcoach/trainer以外の場合ログイン画面へ強制リダイレクトするため、選手アカウントではこの画面自体を開けません）

### 3. コーチ・トレーナー用PCダッシュボード（`dashboard.html`）
- **概要サマリー**：登録選手数、本日の補食実施率、痛み報告数、オプトイン承認待ち数、要注意アラート一覧、本日のトレーニング進捗（ドーナツグラフ）
- **痛み・コンディション監視ボード**：本日の痛み報告一覧、全期間の履歴一覧
- **メニュー配信（セット別強度設定）**：種目名・セット数を指定すると、セットごとの強度（1RMの%）・回数の入力行が自動生成され、各セット個別に設定可能（例：50%→60%→70%→75%→80%とピラミッド式に強度を上げるメニューなど）。全選手または個別選手（リハビリ）へ配信。配信済みメニュー一覧では各セットの強度・回数を一覧表示
- **オプトイン承認**：選手からの希望メニューリクエスト（「その他」の自由入力内容を含む）を承認／却下
- **リハビリ管理**：リハビリ中選手の一覧、フェーズ変更（フェーズ1〜4）、専用メニュー確認、直近の痛み報告履歴
- **振り返り一覧（新規）**：全選手の振り返り投稿を一覧表示し、コーチ・トレーナーからコメントでフィードバック可能
- **選手管理・成長確認（管理者専用・新規）**：選手の**新規登録・情報編集・退部（論理削除）**をこの画面からのみ実施可能。背番号の重複はエラーチェックあり。退部処理は`active`フラグをfalseにする論理削除のため、退部後も過去の記録（トレーニング実績・1RM・振り返り等）は保持される。選手を選択して1RM推移グラフ・本日のコンディションも確認できる。

## 🔗 主要画面のURI
| 画面 | パス | 説明 |
|---|---|---|
| ログイン選択 | `/index.html` | 全ユーザー共通の入口 |
| 選手用アプリ | `/player.html` | 選手ログイン後に遷移（未ログインは自動リダイレクト） |
| PCダッシュボード | `/dashboard.html` | コーチ・トレーナーログイン後に遷移（未ログインは自動リダイレクト） |

※ ログイン状態は `localStorage`（デモ用の簡易セッション）で管理しています。本番運用にはサーバーサイド認証が必要です。

## 🗄 データモデル（Table API / `.tables/schema.json`）

| テーブル名 | 概要 |
|---|---|
| `users` | ユーザー（選手・コーチ・トレーナー）。氏名・役割・リハビリフェーズ・背番号・ポジション・`active`（在籍中フラグ。falseの場合は退部済みとして選手一覧・配信対象から除外するが、履歴データは保持） |
| `daily_conditions` | 日々のコンディション。補食実施チェック・痛みの有無（日付単位） |
| `pain_records` | 痛み記録。コンディションに紐づく部位・レベル（1〜5）・メモ |
| `workout_sets` | ウエイトトレーニング実績。**セット単位**で種目・セット番号・目標/実測の重量・回数・完了フラグを管理 |
| `one_rm_records` | 1RM（最大挙上重量）の履歴。成長グラフの元データ |
| `menus` | 配信メニュー。種目・セット数・対象グループ・カテゴリ（通常/リハビリ/オプトイン）に加え、`intensity_per_set`（セットごとの強度%配列）・`reps_per_set`（セットごとの回数配列）でセット別の内容を保持 |
| `optin_requests` | 選手からの希望メニュー申請。種別・メモ・承認状態。「その他」選択時は `custom_menu_type` に自由入力内容を保持 |
| `workout_reflections` | 選手のトレーニング振り返り投稿（1日1件、更新可） |
| `reflection_comments` | 振り返りへのコメント（選手・コーチ・トレーナーいずれも投稿可） |

初期投入データとして、コーチ1名・トレーナー1名・選手41名（うち1名はACLリハビリ中の設定）、直近1ヶ月分の1RM推移サンプル、本日分のコンディション・トレーニング記録デモデータ（セット別重量差あり）、振り返り・コメントのサンプルを投入済みです。

## 🚧 未実装・今後の推奨開発項目
1. **本番認証の実装**：現在はパスワードなしの簡易ログイン（デモ用）。実運用では安全な認証基盤（SSOなど）の導入が必要です。静的サイトでは真の意味でのセキュアな認証は実現できないため、認証が必要な場合は別途サーバーサイドの仕組みをご検討ください。
2. **通知機能**：痛みの継続や補食未実施をトレーナーへリアルタイムに通知するプッシュ通知・メール連携。
3. **メニュー配信の自動割当ロジック強化**：現状はデモロジックで対象を判定していますが、実運用ではより柔軟なグルーピング（学年・ポジション別など）が求められます。
4. **CSV/Excel入出力**：既存のスプレッドシート運用からの移行支援。
5. **写真・動画添付**：痛みの状態や動作フォームを画像・動画で記録する機能。
6. **多施設・複数チーム対応**：チーム単位でのデータ分離。
