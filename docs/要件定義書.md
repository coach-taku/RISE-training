# KUKI GYMRATS ウエイトトレーニング管理システム
# 要件定義書（現行実装版）

- 対象：KUKI GYMRATS（選手41名体制チーム）
- 作成日：2026-09-10
- 本書は「既に構築済みの現行アプリケーション」の仕様を、指定フォーマットに沿って整理したものである（新規開発の要件ではない）。

---

## 1. 機能要件（画面ごとに整理）

### 共通機能
- **ログイン機能**
  - ログイン画面上に「コーチ・トレーナー」ボタン一覧と「選手（41名）」検索可能グリッドを表示し、名前（アイコン）を選択するだけでログインする。
  - **パスワード・合言葉の入力は不要**（デモ用の簡易ログイン。プルダウンではなくボタン／カード選択方式）。
  - ログイン後のユーザー情報（id・name・role等）は`localStorage`（`Session`オブジェクト）に保存し、各画面はこれを参照して表示・編集対象を判定する。
  - 選手一覧は氏名・背番号でインクリメンタル検索が可能。リハビリ中選手はハイライト表示される。

### 選手向け機能（スマホ最適化・`player.html`）
4タブ構成（ホーム／成長グラフ／振り返り／メニュー希望）で提供。

- **コンディション入力（ホームタブ）**
  - 補食実施の有無をON/OFFトグルで記録（即時保存）。
  - 痛み・違和感の有無をトグルで記録し、ONの場合は人体シルエット図（ボディマップ）から痛みの部位をタップ選択、5段階の痛みレベルとメモを入力。
  - リハビリ中の選手には専用の注意バナーを表示。
- **トレーニング入力機能（ホームタブ）**
  - スタッフが事前配信した「本日のメニュー」を種目カード単位で表示。
  - **種目単位ではなくセット単位**で重量・回数を入力（同一種目内でもセットごとに強度・重量を変えられる：例）ウォームアップ→本セットのピラミッド式）。
  - 目標重量は、選手の直近1RM×セットごとの強度(%1RM)から**自動算出**。
  - 各セットの実測重量（＋/−、2.5kg単位）・実測回数（＋/−、1回単位）を個別に調整。
  - セットごとに「完了」チェックが可能。**完了後も重量・回数・完了状態はいつでも再修正可能**（記録をロックしない）。
  - フォームの感覚・気づきは「振り返り」タブで自由記述として入力する（種目メモではなく1日単位の振り返りとして実装）。
- **ダッシュボード（成長の可視化・成長グラフタブ）**
  - 過去のトレーニング記録（1RM履歴）をもとに、種目ごとの1RM（最大挙上重量）の推移を折れ線グラフ（Chart.js）で表示。
  - 直近1RM・期間内の伸びを数値表示。
  - ※体重比指標（体重に対するMAX重量の比率）は現行未実装。
- **振り返り機能（振り返りタブ）**
  - 本日のトレーニングに関する振り返り（できたこと・課題・体の状態等）を記入・更新（1日1件、上書き更新可）。
  - チーム全員の振り返り投稿を時系列で閲覧できる。
  - 他選手・コーチ・トレーナーの投稿にコメントを送信できる（コメントスレッド形式）。
- **メニュー希望（メニュー希望タブ・オプトイン）**
  - 用意された選択肢（例：ジャンプ力向上プログラム等）から希望メニューを申請。
  - 選択肢に「その他」を用意し、選択時は自由入力テキストボックスで希望内容を記入可能。
  - 自身の申請履歴と承認状況（承認待ち／承認済み／却下）を確認できる。

### スタッフ（コーチ・トレーナー）向け機能（PC最適化・`dashboard.html`）
サイドバー7ビュー構成（概要サマリー／痛み・コンディション監視／メニュー配信／オプトイン承認／リハビリ管理／振り返り一覧／選手管理・成長）で提供。

- **メニュー登録機能（メニュー配信ビュー）**
  - 種目名・セット数を入力すると、セット数に応じた「強度(%1RM)・回数」の入力行が自動生成される。
  - **セットごとに個別の強度・回数を設定可能**（例：50%→60%→70%→75%→80%のピラミッド式メニュー）。
  - 配信対象を「全選手」または「個別選手（リハビリ対象等）」から選択して配信。
  - 配信済みメニュー一覧をセットごとの強度・回数付きで確認できる。
- **選手データ確認機能（チーム全体・個別）**
  - **概要サマリー**：登録選手数、本日の補食実施率、本日の痛み報告数、オプトイン承認待ち数、要注意アラート一覧（痛み報告のある選手）、本日のトレーニング進捗（完了／未完了セット数のドーナツグラフ）を確認。
  - **痛み・コンディション監視**：本日の痛み報告一覧、全選手・全期間の痛み履歴一覧を確認。
  - **選手管理・成長ビュー**：選手を選択し、その選手の1RM推移グラフ・当日のコンディション（補食実施・痛みの有無）を確認し、指導のフィードバックに活用できる。
- **オプトイン承認機能**
  - 選手からの希望メニュー申請（「その他」の自由入力内容を含む）を一覧表示し、承認／却下を行う。
- **リハビリ管理機能**
  - リハビリ中の選手一覧を表示し、フェーズ（フェーズ1：急性期〜フェーズ4：競技復帰の4段階）を変更。専用メニュー・直近の痛み報告履歴を確認。
- **振り返りコメント機能**
  - 全選手の振り返り投稿を一覧表示し、コーチ・トレーナーからコメントでフィードバックできる。
- **選手管理機能（管理者限定・新規／既存要件）**
  - 選手の**新規登録**（氏名・背番号・ポジション・リハビリフェーズを入力）は、本ダッシュボードの「選手管理・成長」ビューからのみ実行可能。
  - 登録済み選手の**編集**（同フォームで情報を更新）。
  - 選手の**退部処理**（確認ダイアログ後、`active`フラグを`false`にする論理削除。過去の記録は保持される）。
  - 背番号の重複はエラーチェックにより登録・更新不可。
  - **選手ロールでログインした場合、本ダッシュボード自体にアクセスできない**（ログイン画面へ強制リダイレクト）ため、選手による自己登録・自己編集は不可能。ログイン画面（`index.html`）・選手用アプリ（`player.html`）にも登録・編集の入口は存在しない。

## 2. 非機能要件

### 開発方式
- コーディングはAIエージェント（Genspark AIエージェント）で実施。
- 人によるコード直接編集は行わない（本エージェントとの対話による指示・修正のみ）。

### データベース
- **Supabase（PostgreSQL）は使用していない**。
- Genspark環境が提供する **RESTful Table API**（`tables/{table}`エンドポイント、GET/POST/PUT/PATCH/DELETE）を使用してデータを永続化。
- テーブル定義は`TableSchemaUpdate`により管理し、データ構造に基づいて9テーブルを設計済み（後述）。
- RLS（Row Level Security）に相当する仕組みは存在せず、フロントエンドJavaScriptからテーブルAPIへ直接アクセスする構成（Supabaseのanonymous key相当の概念は本環境にはない）。

### ホスティング・デプロイ
- **VercelおよびGitHub連携の自動デプロイは使用していない**。
- Genspark環境の **「Publishタブ」／Hosted Deploy機能** を用いて、Cloudflare Workers上にホスティングする。
- 本番反映は、ユーザーがPublishタブから手動で公開操作を行うか、エージェントに明示的に「Hosted Deploy」を依頼した場合にのみ実行される（mainブランチ連携の概念はない）。

### 対応デバイス
- 選手用画面（`player.html`）：スマートフォン最適化（モバイルファースト、下タブバーによる操作）。
- スタッフ（コーチ・トレーナー）用画面（`dashboard.html`）：PC最適化（サイドバー＋メインコンテンツのレイアウト）。タブレット等でも一定の閲覧は可能だが、専用のレスポンシブ最適化は限定的。

### セキュリティ・認証設計（シンプル構成・現行実装）
- **認証UI**
  - プルダウンではなく、コーチ・トレーナーのボタン一覧／選手の検索可能カード一覧から名前を選択する方式。
  - **全員共通の合言葉（パスワード）入力は現行実装にはなく、名前選択のみでログインが完了する**（ご提示の新要件より簡易な構成）。
  - メールアドレス入力・パスワードリセット等の高度なUIは実装していない。
- **裏側の実装**
  - Supabase Authは使用していない。
  - `users`テーブルに`id`・`name`・`role`を保持（**`password`カラムは現行実装にはない**）。
  - ログイン処理は、選択されたユーザーのレコードをそのまま`Session.setUser()`で`localStorage`に保存する（パスワード一致確認のロジックはない）。
  - 各画面は`localStorage`のユーザー情報を参照してデータを絞り込む：
    - `role`が`player`の場合 → 自分自身の`user_id`に紐づくコンディション・トレーニング記録・振り返り等のみを対象に表示・入力する。
    - `role`が`coach`／`trainer`の場合 → 全選手のデータを閲覧・管理できる（`dashboard.html`）。
  - `dashboard.html`側では、`role`が`coach`／`trainer`以外（未ログイン・`player`）の場合は`index.html`へ強制リダイレクトするガード処理があり、選手が管理機能（選手登録・編集・退部等）へアクセスすることを防止している。
  - ⚠️ 本認証はサーバーサイドの検証を伴わないクライアント側制御であり、真にセキュアな認証・アクセス制御ではない（本番運用移行時は別途強化が必要）。
- **初期データ**
  - コーチ1名・トレーナー1名・選手41名（うち1名はACLリハビリ中）を`users`テーブルに投入済み。
  - 直近1ヶ月分の1RM推移サンプル、本日分のコンディション・セット別トレーニング記録、振り返り・コメントのサンプルデータも投入済み。

### 環境変数
- `NEXT_PUBLIC_SUPABASE_URL`／`NEXT_PUBLIC_SUPABASE_ANON_KEY`等の環境変数は**存在しない**（Next.js／Supabase構成ではないため該当なし）。
- Table APIへの接続はGenspark環境側で自動的に設定されており、開発者・利用者が環境変数を意識する必要はない。

### UIデザイン（見た目・制約）
- 動画のアップロード・閲覧機能は実装していない（シンプル・軽量構成）。
- チームカラーを基調としたデザイン：
  - 背景色：**ダークグレー〜ブラック系**（`#0f1115`／`#16181d`等）
  - メインカラー：**レッド**（`--kuki-red`）
  - アクセント：白系文字・グレー系サブテキストで視認性を確保
  - フォント：Google Fonts（Oswald＋Noto Sans JP）、アイコン：Font Awesome

## 4. データ構造（現行 `.tables/schema.json`）

### 1. `users` テーブル（ユーザー情報）
| カラム名 | データ型 | 説明 |
| --- | --- | --- |
| id | text (PK) | 一意のID |
| name | text | 氏名 |
| role | text | 権限（`player`／`coach`／`trainer`） |
| rehab_phase_id | text | リハビリフェーズID（`phase_1`〜`phase_4`、任意） |
| jersey_number | number | 背番号（在籍中選手内で重複不可） |
| position | text | ポジション／グループ |
| active | bool | 在籍中フラグ。`false`の場合は退部済み（論理削除） |

### 2. `menus` テーブル（コーチ・トレーナーが登録するメニュー）
| カラム名 | データ型 | 説明 |
| --- | --- | --- |
| id | text (PK) | 一意のID |
| exercise_name | text | 種目名 |
| sets | number | セット数 |
| reps | number | 基本回数（セット別未設定時の共通値） |
| intensity_percent | number | 基本強度%（セット別未設定時の共通値） |
| intensity_per_set | array | セットごとの強度%配列（例：[60,70,75,80,80]） |
| reps_per_set | array | セットごとの回数配列（例：[8,6,5,5,5]） |
| target_group | text | 配信対象（`all`／`rehab`／`optin_jump`／個別ユーザーIDなど） |
| category | text | 分類（`normal`／`rehab`／`optin`） |
| note | text | メモ |
| created_by | text | 作成者ID |
| date | text | 配信日 |

### 3. `workout_sets` テーブル（選手のトレーニング記録）

## 5. 要件との主な差分まとめ

| 項目 | 提示要件 | 現行実装 |
|---|---|---|
| ログイン認証 | 名前選択＋共通パスワード | 名前選択のみ（パスワードなし） |
| インフラ | Supabase＋Vercel＋GitHub連携 | Genspark Table API＋Hosted Deploy（Cloudflare） |
| カラー | ネイビー×イエロー×白 | ダーク×レッド |
| トレーニング記録の粒度 | 種目単位（重量・回数・セット数を1件） | **セット単位**（セットごとに重量・回数、目標重量は1RM自動算出） |
| 体重比MAX指標 | あり | なし（`body_weight`列なし） |
| 痛み・コンディション管理 | なし | あり（補食チェック・ボディマップ・5段階痛みレベル） |
| 振り返り・コメント | メモ欄のみ（種目単位） | 独立機能（1日単位の振り返り＋チーム内コメントスレッド） |
| メニュー希望（オプトイン） | なし | あり（その他自由入力・承認フロー） |
| リハビリ管理 | なし | あり（フェーズ1〜4管理） |
| 選手登録権限 | 言及なし | コーチ・トレーナー（管理者）限定、選手の自己登録不可 |
